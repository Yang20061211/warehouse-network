# 城际仓网规划系统去除 AI 味设计

## 目标

在 `codex/remove-ai-slop` 分支上，把项目从“模板化产品展示”调整为务实的课程设计工具，同时保留现有功能、页面入口和算法行为。

用户已选择“务实课程项目风”：

- 界面准确、克制、便于操作和答辩；
- 不用渐变、光晕、英文品牌口号、营销式标签和堆叠指标卡；
- 代码与文档只保留能解释问题或验证结果的内容；
- 不新增功能，不更换 Java/Swing 技术栈。

## 成功标准

1. 登录、角色隔离、城市增删改查、距离排序、邻接表、Prim/Kruskal、Dijkstra 和算法对比均可继续使用。
2. 初始数据仍为 30 城、435 条无向边、870 个邻接边结点、29 条 MST 边，MST 总权值保持 117.97。
3. 登录页不再呈现官网式双栏视觉；主界面采用浅色、低饱和、少装饰的桌面工具风格。
4. UI 文案直接描述功能，不出现口号、夸张承诺或重复的“工程实现”包装。
5. 删除明确未使用的代码和小型重复辅助项，不做与去 AI 味无关的算法重构。
6. README 和实验报告不再声称仓库中不存在的自动化测试；截图和性能数据在重新验证后更新。

## 非目标

- 不改变链表、邻接表、MST 或最短路径的计算口径。
- 不改变账号、角色权限、数据文件格式和启动方式。
- 不引入新依赖、构建系统、数据库或 Web 前端。
- 不重写算法层，也不以大改架构来追求“更专业”。
- 不清理与本任务无关的既有问题。

## 约束

- Swing 没有现成的现代主题，视觉调整必须继续使用 JDK 标准库。
- 当前机器没有可用 Java 运行时，首次验证前需要临时获取 JDK 17；建议只用于本次任务，不修改系统默认 Java。
- 改动必须保持在独立分支，不合并、不推送主分支。
- 每一步先完成一个范围明确的清理，再重新编译、自检和检查截图。

## 方案

### 方案 1：务实课程项目风（已选）

保留现有信息架构，但去掉模板化包装：

- 登录页改为单列登录表单，保留账号、密码和两个演示入口；
- 主界面改为浅色侧栏与简洁标题栏，保留导航、状态栏和必要图标；
- 使用中性灰背景、深色文字和低饱和青绿色强调色；
- 统一使用小圆角或直角边框，取消渐变、光晕和装饰性网络图；
- 指标区域压缩为更直接的数据行或轻量小卡，减少卡片套卡片；
- README 和报告改为陈述功能、结构、结果和限制。

代价是需要同时调整 `Theme`、`Ui`、登录页和主框架，视觉回归面比只改文案大。

### 方案 2：原生 Swing 工具风（未选）

几乎取消自绘组件，只保留地图、图表等必要绘制。AI 味最低且代码最少，但界面明显朴素，课程答辩时的信息层级可能变差。

### 方案 3：只改文案与死代码（未选）

风险最小，但深色侧栏、蓝色主色、渐变登录页和官网式标题仍然存在，无法整体解决用户指出的 AI 味。

## 具体改动

### 第一遍：界面视觉与文案

- 调整 `Theme` 配色和字体层级，移除高饱和模板蓝色；
- 重做 `LoginFrame` 为简洁登录窗口，删除品牌插画、网格、双光晕、英文副标和口号标签；
- 调整 `MainFrame` 的标题栏、侧栏、身份信息和状态栏，保留角色导航与截图接口；
- 收敛 `Ui` 的卡片、按钮、标签和输入框样式，去掉不必要的视觉层；
- 保留地图、图表、表格和路径高亮，因为它们承担实际功能；
- 将各页副标题和提示语改为短、具体、无营销色彩的表述。

### 第二遍：代码噪声

- 删除未使用的 `Ui` 辅助方法：`vbox`、`hbox`、`title`、`muted`、`alpha`、`millisShort`、`softCard`、`info`；
- 删除未使用或无调用的模型/角色方法：`City.withName`、`Graph.vertex`、`Role.getDescription`；
- 删除装饰性 ASCII 分隔线和只复述下一行代码的注释；
- 保留解释链表指针、排序稳定性、MST 口径和 Dijkstra 行为的注释；
- 不合并算法逻辑，不为减少行数做高风险抽象。

### 第三遍：文档与截图

- 精简 README 的营销式描述，保留运行方式、账号、功能、项目结构和已验证数据；
- 修正实验报告中不存在的“服务层自动化测试”和“界面回归测试”声明；
- 把性能数字集中到有日期、JDK 和硬件的可复现记录中，删除前后不一致的重复数字；
- UI 修改完成后重新生成截图，并替换 README/报告中的旧截图；
- 删除不再对应的旧截图和图片引用。

## 验证计划

1. 临时获得 JDK 17，在修改前执行编译、`--selftest` 和截图基线。
2. 每完成一遍改动后重新编译并运行自检。
3. 核对固定不变量：30 城、435 条无向边、870 个边结点、29 条 MST 边、总权值 117.97。
4. 逐页查看登录页、管理员页面、查询员页面和路径页面截图。
5. 检查 README 与报告中的图片链接、账号、命令和性能声明是否与当前仓库一致。
6. 检查 `git diff`，确认没有算法行为改动、无关文件改动或主分支合并。

## 风险与回退

- 视觉改动可能压缩表格或地图空间，需要按最小窗口尺寸检查。
- Swing 字体在不同系统上可能变化，截图只能代表当前机器，不据此承诺像素级一致。
- 临时 JDK 仅用于构建和自检；如果无法获得，实施会停在“代码已改但无法完成运行验证”的状态，不能声称验证通过。
- 所有改动保留在分支中，可通过 Git diff 回退，不影响 `main`。
